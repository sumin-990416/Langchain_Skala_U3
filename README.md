# 배터리 분석 AI 스타트업 투자평가 Agentic RAG

> **SKALA 4기 · 울산 3반 · 4조 프로젝트** (팀원: 김대훈, 강도희, 이연주, 정수민, 손연우)
> LangGraph 기반 다중 에이전트(Multi-Agent)와 Agentic RAG를 활용하여, 배터리 분석 AI 스타트업의 비정형 문서를 수집·검증하고 5가지 서로 다른 투자 관점으로 병렬 평가하여 최종 투자 검토 보고서를 자동 생성하는 AI 파이프라인입니다.

---

## 1. 도메인과 문제 정의 (Domain & Problem)
- **대분류**: Energy / **세부 분야**: Battery Intelligence · BMS · ESS 분석 AI
- **문제 인식**: 투자자는 배터리 AI 스타트업의 핵심 기술, 실제 성능, 고객 실적을 평가해야 하나, 기업마다 공개 지표와 시험 조건(SOC, SOH, RUL 등)이 다르고 자체 주장과 독립 검증이 혼재되어 직접 비교가 매우 어렵습니다.
- **해결책**: 단순 검색이나 LLM 요약이 아닌, **사실(Evidence) 수집과 투자 성향(Investment Profile) 판단을 완벽히 분리**하여 다수결 합의 및 이견 분석을 수행하는 의사결정 시스템을 구축합니다.

---

## 2. 핵심 설계 원칙 및 시스템 아키텍처

본 시스템은 **공통 근거를 만드는 Evidence RAG Subgraph**와, 동일한 근거를 바탕으로 각기 다른 가중치와 투자 철학으로 해석하는 **5개의 Profile Agent**로 구성됩니다.

### ⚙️ Graph 전체 흐름 (Workflow)

```mermaid
flowchart TD
    A([START]) --> B[고정 기업 3곳과 문서 코퍼스 로드]
    B --> C[현재 기업 선택]
    C --> D[29개 항목 평가 질문 생성]
    D --> E[Evidence RAG 검색]
    E --> F[관련성·출처·상충 검증]
    F -->|근거 충분| G[공통 영역점수·근거충족률 계산]
    F -->|부족·retry < 2| H[Query Rewrite]
    H --> E
    F -->|retry = 2| I[미확인 항목 기록]
    I --> G
    G --> J[5개 Profile Agent 병렬 실행]
    J --> K[Agent 결과 종합·최종 투자지표]
    K --> L[기업 결과 저장]
    L --> M{남은 기업?}
    M -->|예| C
    M -->|아니오| N[기업 간 비교]
    N --> O[투자보고서 구조화 데이터 생성]
    O --> P[인용·수치·REFERENCE 검증]
    P -->|오류| O
    P -->|통과| Q([END])
```

- **재검색(Query Rewrite) 조건**: 관련성이 떨어지거나 독립적인 확인 자료가 없는 경우 질의를 수정하여 최대 2회 재검색합니다.
- **환각(Hallucination) 방지**: 끝내 찾지 못한 정보는 임의로 추정하지 않고 `Unknown(미확인)`으로 처리하여 근거 충족률(`Evidence Coverage`)을 낮춥니다.

## 3. Evidence RAG 전략

### 문서 설계 및 임베딩 모델
- **코퍼스(Corpus)**: ACCURE, volytica, Electra 등 분석 대상 기업의 백서, 고객 사례, 특허, 외부 논문, 시장/규제 자료 (최대 200쪽 분량)
- **임베딩 모델**: `BAAI/bge-m3` (다국어 한국어·영어 혼합 검색 지원 및 전문 용어 성능 우수)
- **청킹 및 검색**: 표/제목 구조를 유지하여 Chunking(크기 500, 오버랩 50) 수행. 검색 시 문서 다양성을 확보하기 위해 초기 **Top-K는 5**로 설정.

### 근거 등급 체계 (Evidence Grade)
판단에 사용되는 모든 사실은 출처의 신뢰도에 따라 등급이 부여됩니다.
- **[A]**: 규제기관, 특허청, 독립 시험기관, 고객 원문 (사실 확인의 주 근거)
- **[B]**: 회사 공식 제품 문서, 실명 고객 사례 (조건 확인 후 보조 근거)
- **[C]**: 회사 홈페이지, 보도자료, 자체 주장 (단독 고득점 제한)
- **[U]**: 출처 불명확, 상충 (점수 산정에서 제외)

## 4. 다중 에이전트 평가 (Multi-Agent Evaluation)

### 4-1. 공통 점수 계산 (`score_domains`)
수집된 근거를 바탕으로 5대 영역별로 1~5점 척도(또는 미확인)를 매기고, 공식 `[Σ(rᵢ × wᵢ) / Σ(확인된 항목의 wᵢ)] × 20` 을 통해 **100점 만점의 객관적 공통 점수**를 산출합니다.
- **평가 영역**: 기술 경쟁력 / 시장성 / 재무·고객 실적 / 안정성 / 팀·사업 실행력

### 4-2. 5대 Profile Agent 병렬 실행
도출된 공통 점수와 검증된 근거를 5명의 전문 에이전트에게 동시(`Send` API)에 전달합니다. 동일한 사실도 에이전트의 성향과 가중치에 따라 다르게 해석됩니다.

| Agent | 핵심 책임 (Focus) | 가중치 우선순위 |
|---|---|---|
| **기술중심형** | 데이터/모델 아키텍처, BMS 연동, 기술 특허 확장성 | 기술(35%), 시장(20%), 팀(20%) |
| **사업성중심형**| 수익모델, 고객 확보, 팀 실행력, KPI 달성 타당성 | 팀(30%), 시장(25%), 재무(20%) |
| **성장형** | AI 확장성, 고객/제품 파이프라인 확장 가능성 | 시장(35%), 기술(20%), 팀(20%) |
| **안정형** | 재무 연속성, 데이터 권리, 규제/안전(제조물 책임) | 재무(30%), 안정성(30%) |
| **균형형** | 전 영역 편향 점검 및 공통 기준 평가 | 전 영역 균등(각 20%) |

## 5. 설치 및 실행 방법

### 1) 환경 세팅
Python 환경에서 필요한 패키지를 설치하고 루트 경로에 `.env` 파일을 생성합니다.
```env
OPENAI_API_KEY=sk-...
```

### 2) 데이터 준비
분석하고자 하는 기업의 실제 문서(PDF, DOCX, TXT)를 `data/raw/` 폴더에 위치시킵니다.

### 3) 파이프라인 실행
터미널에서 아래 명령어를 실행하면, **FAISS 임베딩 ➔ 다중 기업 평가(Loop) ➔ 5개 에이전트 병렬 분석 ➔ 마크다운 보고서 자동 생성**이 차례로 진행됩니다.
```bash
uv run python main.py
```

### 자동 생성 투자 보고서 (`output/final_multi_agent_report.md`)
최종적으로 3개 기업에 대한 종합 비교표와, 에이전트 간의 의견 편차(Standard Deviation)가 담긴 최대 5장 분량의 심사 보고서가 자동 생성됩니다.

```markdown
# 투자 심사 요약 보고서 (Multi-Agent RAG)

## 1. 종합 비교표
| 기업 | 기술 | 시장 | 재무 | 안정성 | 팀·사업 | 근거충족률 | 최종 점수 | 판정 |
|---|---|---|---|---|---|---|---|---|
| ACCURE | 90.0 | 80.0 | 70.0 | 84.0 | 96.0 | 85.0% | 84.1 | 투자검토 추천 |

## 2. 기업별 상세
### ACCURE (투자검토 추천)
- **평균 점수**: 84.1점 (표준편차: 1.6)
- **근거 충족률**: 85.0%

#### Profile Agent 결과
- **기술중심형**: 86.3점 - ACCURE는 배터리 관리 솔루션에서 뛰어난 기술력을 보유하며 BMS/ESS 연동의 기술적 타당성이 매우 높음.
- **안정형**: 81.3점 - 기술은 훌륭하나, 고객 실적의 독립적 검증이 부족하며 재무 안정성에 대한 보수적 접근이 필요함. (추가 실사 요망)
...
```

> **Insight**: 위 결과를 통해, 배터리 솔루션의 뛰어난 성능으로 인해 **기술중심형** 에이전트는 `86.3점`의 고득점을 부여한 반면, 재무와 데이터 출처를 엄격하게 따지는 **안정형** 에이전트는 `81.3점`이라는 가장 짠 점수를 부여했음을 알 수 있습니다. 이처럼 의도적인 **"관점의 충돌과 토론"**을 통해 투자 리스크를 다각도에서 검증하는 것이 본 시스템의 강력한 장점입니다.
